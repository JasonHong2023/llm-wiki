# 會議記錄與摘要

用 Claude 將雜亂的會議記錄轉化為結構化筆記、行動項目和主管摘要。

## 你將學到什麼

- 如何將原始逐字稿或粗略筆記轉化為結構化、可行動的會議摘要
- 如何從無結構的對話中提取決策、行動項目和負責人
- 如何為不同受眾量身打造摘要——從詳細的團隊筆記到一段話的主管簡報

## 使用情境

大多數會議產生兩個結果：沒人看的錄影，以及一組慢慢從所有人記憶中消退的半記得的行動項目。會議記錄的問題是真實存在的——有人必須做記錄，要做好很繁瑣，如果沒有在會後數小時內完成，關鍵背景資訊就會永久消失。

Claude 可以大幅縮小這個落差。無論你有自動轉錄工具的原始逐字稿、會議中記下的條列式筆記，還是以文字形式彙整的粗略音頻錄音，Claude 都能將這些非結構化的輸入轉化為乾淨、有結構的摘要，讓人實際閱讀並採取行動。

這對於週期性會議（每週站會、sprint 回顧、客戶電話）、有許多與會者和並行討論的大型團隊會議，以及任何需要為不在場的人記錄決策的會議特別有價值。對於你想保持承諾和回饋長期記錄的一對一會議也很有用。

這個工作流程可以擴展：一個 15 分鐘的站會可以在 30 秒內完成摘要。一個有 12 人參與的兩小時戰略規劃會議可能需要 5–10 分鐘的提示才能做好。無論如何，這都比手動完成更快更好。

## 逐步指南

### 第一步：收集原始輸入

Claude 可以處理多種類型的輸入——使用你有的：

- **自動生成的逐字稿**— 來自 Zoom、Google Meet、Otter.ai 或類似工具。這是最豐富的輸入，能產生最好的輸出。
- **粗略筆記**— 你在會議期間打的條列式筆記，即使不完整或順序混亂也沒關係。
- **你的記憶**— 如果沒有逐字稿，你可以用對話的方式向 Claude 描述會議，並請它整理你的回憶。

如果使用逐字稿，不需要先清理它。帶有說話者標籤、填充詞和連篇句子的原始逐字稿都沒問題——Claude 處理得很好。

### 第二步：在逐字稿前提供會議背景資訊

在貼上逐字稿之前，給 Claude 會議的元數據。這讓它能正確地解讀所讀到的內容：

- 會議名稱和日期
- 與會者及其職位
- 會議的既定目的或議程
- 任何 Claude 應該知道的重要背景

範例背景資訊：「這是我們 2026 年 3 月 18 日每週產品團隊站會的逐字稿。與會者：Sarah（PM）、Marcus（工程主管）、Priya（設計）、Tom 和 Lena（工程師）。站會格式是：昨天做了什麼、今天要做什麼、有任何阻礙嗎。」

### 第三步：指定你需要的輸出格式

不同的會議和不同的受眾需要不同的摘要。明確說明你想要什麼：

- **完整會議記錄**— 全面的、按議程項目整理的，適合錯過會議的團隊成員
- **行動項目清單**— 任務、負責人和截止日期的重點提取
- **主管摘要**— 1–3 段涵蓋做出的決策及原因，給不在現場的利害關係人
- **決策日誌**— 僅包含做出的決策，附簡短的理由和決策者
- **跟進郵件**— 一封準備好發送的郵件，向與會者總結會議

你可以在一個提示中請求多種格式：「先給我完整的會議記錄，然後在下面附上一個單獨的部分，只列出行動項目的待辦清單。」

### 第四步：審閱並修正

Claude 的摘要在結構上會很好，但它可能誤歸引用、遺漏細節，或提取出實際上已被否決的行動項目。永遠要對照你的原始筆記或記憶審閱輸出。對於高風險的會議，在發布前請另一位與會者審閱。

如果有任何錯誤，以對話的方式修正：「第 3 項的決策實際上是將發布推遲到 Q3，而不是 Q2。請修正這一點並重新生成摘要部分。」

### 第五步：以正確格式發布

摘要準確後，請 Claude 為你的發布管道格式化：

- **郵件**：「將這個格式化為一封乾淨的郵件，行動項目以項目符號待辦清單的形式放在最上方。」
- **Notion/Confluence**：「以 Markdown 格式呈現，帶有適當的標題和行動項目的核取方塊。」
- **Slack**：「給我一個可以在 Slack 上發布的簡縮版——保持在 300 字以內，使用純文字，不要 Markdown 標題。」

## 提示範本

```
請總結以下會議逐字稿/筆記。
**會議背景資訊：**
- 會議名稱：[例如，「Q2 產品規劃」]
- 日期：[日期]
- 與會者：[姓名和職位]
- 目的：[這次會議應該完成什麼？]
**我需要的輸出格式：**
[ ] 完整會議記錄（按議程項目整理）
[ ] 行動項目清單（任務、負責人、截止日期）
[ ] 主管摘要（最多 3 段）
[ ] 決策日誌（決策 + 理由）
[ ] 跟進郵件草稿
**特別說明：**[需要特別注意的事項、要使用的術語，或需要強調的部分]
---
[在此貼上你的逐字稿或筆記]
```
## 技巧與最佳實踐

- 
**永遠包含與會者職位**— 當 Claude 知道 Marcus 是工程主管而 Sarah 是 PM 時，它能對誰負責哪個行動項目做出更聰明的推斷。沒有職位，它只能使用姓名，這會產出較不實用的輸出。
- 
**請 Claude 標記不清楚的項目**— 添加「如果逐字稿中有任何模糊不清的地方——尤其是關於決策或行動項目負責人——請用 [不清楚] 標記，而不是猜測。」這可以防止你的最終筆記出現聽起來有信心但實際上錯誤的內容。
- 
**對週期性會議使用重複範本**— 如果你有每週團隊站會，設計一次摘要格式並儲存提示。每週只需貼上新的逐字稿。你的團隊會開始期待一致的格式，這讓筆記更有用。
- 
**分割非常長的逐字稿**— 對於超過 90 分鐘的會議，逐字稿可能太長而無法在一次處理中很好地運作。按議程部分分割，分別摘要每個部分，然後請 Claude 從各部分的摘要中合成一個總摘要。
- 
**將摘要轉化為專案記憶**— 不要讓會議記錄只存在於郵件討論串中。請 Claude 提取關鍵決策並將其添加到你的專案持續決策日誌中。隨著時間推移，這會建立一個可搜索的記錄，說明為什麼你的專案是現在這個樣子。

## 動手試試

找一個你上週參加的會議——如果有自動逐字稿就取得，或花 3 分鐘從記憶中寫下關於討論了什麼、決定了什麼、分配了什麼的粗略筆記。

將上面的提示範本貼入 Claude，附上你的會議背景資訊，勾選「完整會議記錄」和「行動項目清單」，然後貼入你的原始素材。

審閱輸出，並請 Claude 做一個改進——無論是修正不準確的地方、調整語氣，還是添加你想要的部分。結束後，你將從可能已經遺失的素材中得到乾淨的會議文件。
